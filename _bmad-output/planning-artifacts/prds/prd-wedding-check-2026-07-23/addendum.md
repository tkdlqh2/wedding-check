# Addendum — 웨딩홀 스캔 오퍼레이터 인수인계 시스템

PRD 본문에는 넣지 않았지만 다운스트림(아키텍처, v2 기획)에 필요한 배경 정보.

## v2 확장 방향 (원문서 §3 참고, 이번 계약 미포함)

- **빈도 기반 자동 승격**: PRD §4.5(FR-9)는 인사이트를 "보여주기"만 하지만, v2에서는 일정 횟수 이상 반복된 원인을 §4.1 템플릿에 자동 편입시키는 기능을 검토한다. 핵심은 세 가지 별도 컴포넌트다 — (1) 반복 횟수 상태 누적, (2) 승격 정책(몇 회 이상이면 후보로 올릴지) 관리, (3) 템플릿 변경에 대한 사람의 승인 절차. 이 세 가지가 v1과 별도 단계로 진행되어야 하는 이유이며, 계약서-시료제작예약시스템 문서의 "v1.1 별도 계약" 처리 방식과 동일한 구조로 제안 예정.
- **다른 웨딩홀 사업체(타사) 확장**: 2026-07-24 업데이트로 "한 사업체 내 다수 홀" 지원은 v1 스코프로 앞당겨졌다(§4.1 FR-1, §8.1 참고). v2로 남은 것은 타사 확장(멀티테넌시) — 사업체 간 데이터 격리, 사업체별 관리자 계정·권한 분리다. 변수 케이스 스키마와 검색 로직(§4.3~4.4)은 이미 재사용 가능한 설계로 두는 것이 v2 확장 비용을 낮춘다 — 아키텍처 단계에서 이 재사용 경계를 명확히 그어둘 것.

## 기술-how 후보 (아키텍처 단계에서 결정, PRD 요구사항 아님)

- FR-6/FR-9의 "의미 기반 매칭"은 임베딩 기반 유사도 검색이 유력한 구현 후보. 키워드/태그 완전 일치로는 원문서에서 확인된 실패 사례("주례자가 순서를 바꿈" ≒ "목사님이 애드리브함")를 못 잡는다.
- 영상(FR-2) 저장소: 자체 스토리지 vs 외부 비디오 호스팅(용량·트래픽 비용 vs 관리 편의성 트레이드오프) — 미정.
- LLM 벤더: 미정, 비용/응답속도(§4.3 FR-5의 5초 임계값과 직결) 기준으로 아키텍처 단계에서 벤치마크 필요.
